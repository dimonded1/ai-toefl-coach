# Дима: продукт, архитектура, интеграция

## Твоя зона ответственности

Ты держишь общую картину: зачем продукт нужен, что команда делает в текущем спринте, как frontend, backend, AI и scoring соединяются в один рабочий сценарий.

## Рабочая ветка

- Для личных задач: `Dima`.
- Для финальной интеграции: `main`.

Не делать обычные рабочие изменения напрямую в `main`, если это не финальный merge/release.

## Главная задача

Не дать проекту расползтись в набор отдельных фич. Главный контур:

```text
цель TOEFL → диагностика → слабые зоны → следующий шаг → практика → обратная связь → обновлённый прогноз
```

## Что проверять в задачах

- Есть ли понятная цель изменения.
- Не ломает ли изменение общий пользовательский сценарий.
- Не залез ли участник в чужую зону без причины.
- Обновлена ли документация.
- Есть ли проверка результата.

## Твои задачи по спринтам

### Sprint 0

- Синхронизировать команду.
- Проверить, что все подняли проект.
- Утвердить зоны ответственности.

### Sprint 1

- Принять безопасную структуризацию.
- Не разрешать крупный рефакторинг без тестов.

### Sprint 2

- Утвердить новый dashboard-сценарий.
- Проверить, что главный CTA действительно один.

### Sprint 3

- Принять минимальную защиту AI API.
- Проверить риски Groq key.

### Sprint 4

- Решить вопрос шкалы TOEFL: `0-120` или `1-6`.
- Проверить понятность confidence.

### Sprint 5

- Собрать demo script.
- Провести финальное QA.
