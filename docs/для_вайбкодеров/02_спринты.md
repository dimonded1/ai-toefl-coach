# 02. Спринты

## Sprint 0. Синхронизация

Цель: все участники запускают проект и понимают структуру.

### Задачи

- Дима: проверить `README.md`, `PRODUCT.md`, `docs/*`.
- Гоща: открыть frontend, проверить dashboard и mobile.
- Олег: поднять backend, проверить `/health`, Groq env.
- Андрей: проверить текущие расчёты в `profile.js`.

### Готово, когда

- У всех запускается проект.
- Команда понимает зоны ответственности.
- Есть список задач Sprint 1.

## Sprint 1. Безопасная структуризация

Цель: улучшить структуру без изменения поведения.

### Дима

- Зафиксировать правила веток и PR.
- Обновить документацию после изменений.
- Проверить, что изменения не расходятся с продуктовой целью.

### Гоща

- Вынести inline styles из JS в CSS.
- Не менять бизнес-логику.
- Сохранить текущий внешний вид или улучшить без риска.

### Олег

- Переименовать `gemini` слой в `ai`/`groq` или provider-neutral naming.
- Разделить route и AI service.
- Добавить timeout для Groq.

### Андрей

- Выделить scoring logic в отдельные функции.
- Подготовить контрольные примеры расчёта.
- Проверить, что старый прогноз сохраняется на тех же данных.

## Sprint 2. Dashboard и следующий шаг

Цель: dashboard должен отвечать на вопрос "что делать сегодня".

### Дима

- Утвердить UX-сценарий: цель → диагностика → действие → обратная связь.
- Проверить, что dashboard не превращается в набор виджетов.

### Гоща

- Пересобрать dashboard:
  - Score cockpit.
  - Today focus.
  - Evidence.
- Добавить один главный CTA: `Start focus session`.
- Укрупнить sidebar.

### Олег

- Подготовить API/AI контракт для объяснения рекомендаций.
- Вернуть причины AI-плана структурно.

### Андрей

- Добавить sample size и confidence к прогнозу.
- Разделить progress и proficiency.

## Sprint 3. Backend и AI надёжность

Цель: AI API не должен быть хрупким и небезопасным.

### Дима

- Проверить риски публичного API.
- Принять минимальный уровень защиты для учебной версии.

### Гоща

- Сделать понятные UI-состояния AI:
  - loading;
  - unavailable;
  - fallback;
  - invalid response.

### Олег

- Добавить validation входных данных.
- Добавить rate limit.
- Добавить понятные error codes.
- Валидировать JSON-ответ AI на backend.

### Андрей

- Согласовать data payload для AI:
  - scores;
  - mistakes;
  - totalTasks;
  - confidence;
  - weak zones.

## Sprint 4. Scoring, analytics, данные

Цель: прогноз TOEFL должен быть честнее.

### Дима

- Проверить, понятна ли пользователю логика прогноза.
- Решить, какая шкала основная: `0-120` или новая `1-6`.

### Гоща

- Обновить analytics UI:
  - trends;
  - readiness;
  - mistake recurrence;
  - target pace.

### Олег

- Подготовить backend-модель хранения:
  - users;
  - profiles;
  - attempts;
  - answers;
  - mistake_bank;
  - ai_feedback.

### Андрей

- Ввести difficulty weights.
- Ввести recency.
- Ввести confidence score.
- Добавить контрольные примеры.

## Sprint 5. Polish и демо

Цель: привести продукт к демонстрационному качеству.

### Все

- Проверить свой сценарий end-to-end.
- Убрать явные баги.
- Обновить инструкции.
- Подготовить короткий demo script.

### Готово, когда

- Приложение открывается.
- Dashboard понятен без объяснений.
- AI fallback работает.
- Нет новых ошибок в консоли.
- Команда может показать продукт по одному сценарию.
