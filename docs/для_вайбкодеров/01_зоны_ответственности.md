# 01. Зоны ответственности

## Ветки по участникам

Каждый участник работает в своей ветке:

| Участник | Рабочая ветка | Когда использовать |
|---|---|---|
| Дима | `Dima` | Личные задачи по документации, архитектуре и интеграции. `main` только для финального merge/release. |
| Гоша | `Gosha` | Frontend, UI, dashboard, дизайн-система. |
| Олег | `Oleg` | Backend, AI API, Groq/provider слой, безопасность. |
| Андрей | `Andrew` | Scoring, данные, analytics, confidence logic. |

Перед началом задачи:

```bash
git fetch
git switch <своя-ветка>
git status
```

Не коммитить рабочие задачи напрямую в `main`.

## Дима: продукт, архитектура, интеграция

### Владеет

- Общей логикой продукта.
- Приоритетами спринтов.
- Архитектурными решениями.
- Финальным ревью.
- Документацией.

### Основные файлы

- `PRODUCT.md`
- `README.md`
- `docs/*`
- итоговые review notes

### Что решает Дима

- Что входит в текущий спринт.
- Какой UX-сценарий главный.
- Когда изменение готово к merge.
- Как связать frontend, backend, AI и scoring.

## Гоша: frontend, UI, dashboard

### Владеет

- Dashboard.
- Навигацией.
- Визуальной иерархией.
- CSS и UI-состояниями.
- Удобством интерфейса.

### Основные файлы

- `frontend/index.html`
- `frontend/src/styles/main.css`
- `frontend/src/scripts/app.js`
- частично `frontend/src/scripts/aiPlan.js`, если меняется UI AI-блока

### Что можно менять самостоятельно

- Layout dashboard.
- CSS-классы.
- UI copy.
- Empty/loading/error states.
- Mobile layout.

### Что согласовывать

- Изменение структуры данных профиля.
- Изменение API payload.
- Перенос логики scoring.

## Олег: backend, AI API, безопасность

### Владеет

- Express backend.
- AI provider layer.
- Groq integration.
- Validation.
- Rate limiting.
- Error handling.
- API contracts.

### Основные файлы

- `backend/server.js`
- `backend/routes/*`
- будущие `backend/services/*`
- будущие `backend/prompts/*`
- будущие `backend/validators/*`
- `docker-compose.yml`, если меняется backend-инфраструктура

### Что можно менять самостоятельно

- Внутреннюю структуру backend.
- AI request/response handling.
- Timeout, validation, error codes.
- Provider naming.

### Что согласовывать

- Изменение frontend endpoint.
- Изменение JSON-формата ответа AI.
- Добавление новой базы данных или auth.

## Андрей: scoring, данные, аналитика

### Владеет

- Расчётом TOEFL prediction.
- Progress/proficiency model.
- Confidence score.
- Difficulty weights.
- Mistake bank logic.
- Analytics data model.

### Основные файлы

- `frontend/src/scripts/profile.js`
- `frontend/src/scripts/data.js`
- будущие `frontend/src/scripts/scoring.js`
- будущие data/model docs

### Что можно менять самостоятельно

- Формулы расчёта.
- Веса сложности.
- Confidence logic.
- Модель attempts/answers/mistakes.

### Что согласовывать

- Изменение UI метрик на dashboard.
- Изменение backend payload.
- Переход с localStorage на backend DB.

## Правило пересечения зон

Если задача требует изменить чужой файл, сначала написать в чат:

```text
Нужно затронуть файл <путь>, потому что <причина>. Изменение маленькое/среднее/крупное. Риск: <риск>.
```
